# 家书星球：沉浸式家庭星系与真实多模态记忆 MVP 设计

**日期：** 2026-07-14<br>
**状态：** 已经产品确认，待审阅本文后进入实施计划<br>
**交付窗口：** 10 天<br>
**部署边界：** 应用、PostgreSQL、原始媒体与备份完全运行在本机 Docker；用户逐次授权后，允许将必要内容发送给外部 OpenAI 兼容 AI 服务。

## 1. 产品承诺

> 家书星球帮助一个家庭管理员把每位家人视作一颗星球，保存各自记得的片段，确认彼此共同的故事，并把真实、私密、可追溯的记忆沉淀为能传给未来的家书。

它不是“家庭文件库”，也不是把宇宙皮肤套在表单上。默认体验仍是一片可漫游的家庭星系；用户通过靠近星球、点亮记忆光、确认故事来推进旅程。

## 2. 已确认的产品决定

| 决定 | 结论 |
| --- | --- |
| 首页第一成功 | **留下一段记忆**，而非先完成一封家书或先浏览功能菜单。 |
| 星球概念 | 完整保留。每位家人是一颗星球，是其故事、记忆、外观、人生阶段和关系的容器。 |
| 纪念星 | 完整保留且常驻原家庭关系与星图位置；以 `MEMORIAL` 纪念状态呈现，不迁入孤立星域、不封存为只读档案。 |
| 记忆、共鸣、家书 | 记忆星是最小内容单位；共鸣星轨是待确认的两段真实记忆关系；家书是从已确认记忆中长出的成果。 |
| 隐私 | 是星球、记忆、素材、关系、家书的属性，不再作为平级“隐私星域”主章节。 |
| 工坊与主题 | 保留为某颗星球的低频“编辑外观”能力；不与记录记忆、进入故事并列。 |
| 视觉语言 | 保留当前沉浸式星球、星环、星图、漫游与慢节奏宇宙主题。信息架构收敛不得把产品降级成卡片后台。 |
| 漫游交互 | 必须保留星球旋转、画布漫游、拖拽、放大、缩小与宇宙景深。10 天内采用高质量 2.5D 画布；完整 WebGL/R3F 是后续增强。 |
| AI 与隐私 | 原始资料先本地保存；每次 AI 出站前取得明确授权。AI 只生成待确认草稿，绝不自动认定家庭事实或公开内容。 |
| 家庭协作 | 本 MVP 只有一个家庭管理员账号。多人邀请、成员权限、通知与协同编辑递延。 |

## 3. 概念模型与信息架构

### 3.1 保留的宇宙语言

```text
家庭星系（沉浸式浏览方式）
└── 星球（一个家人）
    ├── 记忆星（已确认的一段真实记忆）
    ├── 人生轨迹（由已确认事件派生的时间线）
    ├── 关系（亲属/长期关系）
    ├── 纪念状态（仍属于该星球，不是另一个产品）
    └── 编辑外观 / 可见范围（低频二级工具）

两段已确认且获授权的记忆
└── 共鸣候选 → 用户确认 → 共鸣星轨

一组已确认、获家书授权的记忆
└── 家书草稿 → 用户编辑确认 → 受控分享快照
```

### 3.2 移除的错误平级关系

以下概念不再作为八个同权“星域”互相争夺首屏：

- `隐私`：改为对象级可见范围与 AI/共鸣/家书授权。
- `主题星云`、`星球工坊`：改为星球详情内的外观编辑入口。
- `共鸣星轨`：改为首页“等待确认”和记忆详情内的候选关系。
- `纪念星域`：改为星球的纪念状态，以及可筛选的纪念视图。
- `星图编辑`：MVP 不再伪装为完整管理器；只有真实数据支撑的“创建家人星球、编辑关系、管理可见范围”才显示。

## 4. 核心体验设计

### 4.1 我的星系：首页仍是星图，不是仪表盘

首页以全屏、可漫游的家庭星图为默认世界。界面只保留轻量的环境信息与两条最重要的行动线：

1. **点亮一颗记忆星**：无论用户当前在星系何处都可触达的“记忆光”。
2. **进入故事**：聚焦某颗星球后自然出现的主入口。

首页可以低打扰地呈现：

- “今天，想为谁留下一段故事？”作为情绪引导，而不是大块表单。
- 正在等待确认的共同记忆，以微光或星轨候选呈现。
- 一封正在生长的家书，以光束/进度语义提示，而不是把家书工坊做成平级导航。
- “打开家庭星图探索”不是另一个页面，而是默认体验本身。

### 4.2 星球详情：一个家人的故事主场

选中星球只完成聚焦、拉近与操作提示；不会错误地宣称已经进入漫游。用户点击清晰的 **进入故事** 后，镜头从星图自然拉近到该星球的故事场景。

星球详情的优先级：

1. 星球表面/封面、姓名、关系、活跃或纪念状态。
2. **进入故事**（唯一主动作）。
3. **记录记忆**（唯一显性次动作）。
4. 已确认记忆星、正在讲述的故事与可确认共鸣。
5. 更多：编辑外观、人生时间线、可见范围、关系、归档/删除。

`MEMORIAL` 星球默认更安静、受保护，但仍可回看、补充记忆、邀请未来版本的家人共同补齐故事、生成纪念家书。它不会自动被隐藏、公开或从关系图中移除。

### 4.3 多模态“记忆光”而非普通表单

用户在场景中触发一段记忆光，进入一个轻量、具有宇宙语义的采集容器。真实表单控件必须存在且可访问，但视觉上是“把一段光放进某颗星球”，不是通用后台表单。

统一流程：

```text
选择星球 → 选择来源 → 本地保存原件 → 明示 AI 授权
→ AI 生成待确认草稿 → 用户编辑/确认 → 点亮真实记忆星
```

支持的输入与明确边界：

| 来源 | 10 天 MVP 支持 | 明确不做 |
| --- | --- | --- |
| 文字 | 直接输入与粘贴，真实 AI 结构化提取。 | AI 自动确认事实。 |
| 图片 | JPEG、PNG、WebP；私有预览，AI 生成可核对的场景描述和记忆草稿。 | 人脸识别、人物自动确认、照片修复、HEIC。 |
| 语音 | MP3、M4A、WAV；最多 10 分钟且单请求不超过 20 MB，异步真实转写。 | 声纹识别、说话人分离、语音克隆、长音频批处理。 |
| 日记文件 | TXT、MD、DOCX、文字型 PDF；先本地提取文本，再把必要片段送入 AI。 | 扫描件/手写 OCR、PDF 图片理解、可执行或嵌入式文档、批量导入。 |

### 4.4 AI 的角色与信任状态

AI 有三种状态，必须在 UI 中清晰可见：

1. **本地保存中 / 等待授权**：原始内容已入本地媒体存储，不会自动出站。
2. **AI 整理中 / 失败可重试**：显示正在发送的素材类型、用途和真实处理状态；没有有效配置时明确报错，绝不静默回退 Mock。
3. **待你确认**：输出标题、时间、地点、人物、情绪、摘要与所有不确定字段；用户可修改、选择可见范围与 AI 使用范围，再确认。

确认后，才允许该记忆：

- 在所属星球上发光；
- 参加已授权的共鸣候选；
- 成为已授权家书的来源；
- 被管理员在未来版本中分享给家庭成员。

### 4.5 共鸣星轨与家书

共鸣不是“AI 发现后自动连线”。它是：

```text
已确认且允许共鸣的真实记忆
→ 规则/语义筛出少量候选
→ AI 解释为什么可能有关
→ 管理员确认或拒绝
→ 才显示为共鸣星轨
```

家书只从已确认、明确允许用于家书的记忆派生。分享仍沿用受控 token 页面，但发布接口只接收已保存的 `bookId` 和分享配置，服务端自行读取合法来源；不能再接受浏览器提交的任意正文或来源声明。

## 5. 漫游与交互契约

### 5.1 手势与结果

| 行为 | 范围 | 结果 |
| --- | --- | --- |
| 拖拽星图空白处 | 画布 | 平移镜头并带轻微惯性，开始自由漫游。 |
| 拖拽已聚焦星球表面 | 选中星球 | 旋转星球纹理与星环角度，不打开管理器。 |
| 滚轮或双指捏合 | 画布 | 缩放镜头；景深、标签密度、星轨细节随距离合理变化。 |
| 点击星球 | 画布 | 聚焦星球、显示名称和操作提示。 |
| 点击进入故事 | 聚焦星球 | 平滑拉近到该家人的故事场景。 |
| 键盘/可见控制 | 画布 | 提供缩放、重置视角、减少动态等替代路径。 |

### 5.2 2.5D 实现原则

MVP 使用现有 React/DOM 星图演进为 2.5D 画布，不在本轮重写为 Three.js/WebGL。画布必须具备：

- 层级景深、轨道平面、星云与粒子稀疏度；
- 与输入连续的镜头平移和缩放；
- 星球表面纹理/照片层的受控旋转、光照和星环视差；
- 选中和进入故事时的空间连续动画；
- 小屏和低性能设备的少粒子、低动态降级。

完整 WebGL/R3F 未来可复用同一套星球、镜头、轨道和手势契约，但不能挤占本轮真实数据闭环时间。

### 5.3 可用性底线

- 只在星图画布内接管拖拽、滚轮、触摸；面板、采集容器和故事详情恢复正常滚动、选择文本和键盘使用。
- 不再对整个工作区无差别 `preventDefault()` 或 `touch-action: none`。
- 所有非手势关键能力有可见按钮、键盘和读屏语义。
- 尊重 `prefers-reduced-motion`；动画可中断，且不阻塞输入。
- 删除和归档必须先确认，并提供撤销窗口；禁止当前的即时、本地内存删除假象。

## 6. 数据真相与本地优先架构

### 6.1 数据域

现有 `User / Galaxy / Planet / SharedBook` 是基础，但不足以承载该产品。新增或演进的领域对象：

| 对象 | 关键内容 | 真相来源 |
| --- | --- | --- |
| `Planet` | 家人身份、关系、位置、外观、`lifeState(ACTIVE/MEMORIAL)`、可见范围。 | PostgreSQL |
| `Memory` | 所属星球、作者、结构化字段、原文、发生时间、可见范围、草稿/确认状态、AI/共鸣/家书授权、版本。 | PostgreSQL |
| `MemoryAsset` | 原始媒体本地键、MIME、大小、哈希、提取文本、转写、处理状态。二进制不放 PostgreSQL。 | PostgreSQL 元数据 + 本地媒体卷 |
| `AiJob` | 素材处理、转写、视觉理解、结构化提取的状态、模型版本、错误摘要、审计信息。 | PostgreSQL |
| `ResonanceCandidate` | 两条真实记忆、候选原因、得分、候选/确认/拒绝状态。 | PostgreSQL |
| `Book` / `BookMemory` | 草稿、章节、来源关系、版本和发布状态。 | PostgreSQL |
| `SharedBook` | 已发布、可撤回的公开分享快照；与现有兼容读取逐步衔接。 | PostgreSQL |

### 6.2 单管理员权限规则

本 MVP 只有当前家庭管理员。所有读写 API 必须先取得会话，再以 `userId`、`galaxyId`、`planetId` 的归属条件查询；不能信任浏览器传来的资源 ID。

可见范围的真实语义：

- `private`：仅管理员。
- `family` 与 `selected`：先保存意图，但在多人功能落地前仍只由管理员实际访问；不能伪称已向他人开放。
- `public`：原始记忆和原始媒体永远不能直接公开。只有用户显式发布的家书快照可通过分享 token 访问。
- 纪念星默认 `private`；每条记忆的 AI 整理、共鸣与家书引用各自独立授权。

### 6.3 本地存储与外部 AI

```text
浏览器
  → 已鉴权的上传/采集 API
  → PostgreSQL（元数据、状态、授权、来源关系）
  → 私有 MediaStore（Docker named volume；原件和派生缩略图）
  → AiJob（用户授权后）
  → 外部 AI Provider Adapter（文本 / 视觉 / 转写 / embedding）
  → 待确认 Memory 草稿
```

`MediaStore` 先以应用可控的本地 Docker named volume 实现，并封装读取接口；未来可在不改变产品契约的情况下切换为本地 MinIO。媒体只能由经过授权检查的应用路由读取，不能暴露宿主机路径或公开静态 URL。备份必须同时覆盖 PostgreSQL 与媒体卷。

外部 AI 适配器必须区分文本、视觉、转写和向量能力，不能假定“OpenAI 兼容”对所有多模态端点都一致。API Key 永远只存在于服务器环境变量。审计只保存模型版本、作业状态、素材引用和请求哈希，不保存完整敏感 prompt。

### 6.4 真实性规则

- `OPENAI_API_KEY` 或相应能力缺失时，生产/本地真实模式返回可理解的配置错误；不自动运行 `mock-ai`。
- Mock 数据只能存在于显式演示模式，UI 必须明显标记“演示资料”。
- `localStorage` 仅可保留尚未上传的临时输入和无业务后果的视图偏好，不再保存记忆、共鸣、家书等领域真相。
- 所有创建、AI 作业启动、共鸣扫描、家书生成和发布使用幂等键；草稿更新使用版本控制，避免重复提交和多标签覆盖。

## 7. API 与状态边界

以下是实施时需要形成的真实主链，具体路由命名可按现有 Next Route Handler 模式调整：

```text
POST   /api/planets                     创建家人星球
PATCH  /api/planets/:id                 更新名称、纪念状态、外观、关系、可见范围
POST   /api/memories/uploads            校验并本地保存素材，创建草稿/Asset
POST   /api/memories                    创建文字记忆草稿
POST   /api/memories/:id/ai-jobs        明确授权后启动 AI 整理
PATCH  /api/memories/:id                编辑草稿
POST   /api/memories/:id/confirm        明确确认后点亮记忆星
POST   /api/resonances/scan             只扫描已确认且获授权记忆
POST   /api/resonances/:id/confirm      确认共鸣星轨
POST   /api/books                       从合法的真实记忆生成/更新草稿
POST   /api/books/:id/shares            创建或更新分享快照
```

每个写接口必须具备：身份认证、资源归属、Zod 级输入验证、MIME/大小/页数/时长限制、幂等处理、可恢复错误和审计日志。

## 8. 错误与边界体验

| 情况 | 用户看到的真实反馈 |
| --- | --- |
| AI 未配置 | “AI 整理尚未配置。原件已安全保存在本机；配置后可继续整理。” |
| AI 失败或超时 | “这段记忆尚未整理完成”，显示重试和保留原件的说明；不回退示例内容。 |
| 不支持的文件 | 明确显示支持格式及原因；不上传或不解析未知/可执行内容。 |
| 文档超限或扫描 PDF | 明确说明当前仅支持文字型文件及限定范围。 |
| 未确认字段 | 在草稿上标记“待你核对”，不隐藏不确定性。 |
| 删除 | 先说明影响、确认后执行，提供撤销窗口；删除媒体遵循可恢复/延迟清理策略。 |
| 空星球 | 显示“这颗星球还没有被写下的故事”，主动作是记录第一段记忆，而不是填充 Demo。 |

## 10. 验收标准

交付日必须能在本地 Docker 完成以下真实演示，且重启服务后结果仍存在：

1. 管理员创建至少两颗真实家人星球，其中一颗可进入纪念模式。
2. 为选定星球提交文字、图片、短音频和一个支持的日记文件；每个原件在本地可受控读取。
3. 用户明确授权后，真实 AI 返回待确认草稿；未配置或失败时没有 Mock 伪装。
4. 用户修改并确认草稿后，记忆以正确的真实 `planetId` 点亮；空星球没有演示内容回退。
5. 两段真实、已确认、获授权的记忆生成可解释的共鸣候选；确认后才显示星轨。
6. 家书只从已确认且允许用于家书的真实记忆生成；发布页通过 token 正确读取快照，原始媒体不公开。
7. 星图支持拖拽漫游、缩放、聚焦、星球旋转、进入故事、重置视角和减少动态；打开采集或详情面板后滚动与键盘不被画布阻断。
8. 删除/归档、上传失败、AI 失败、权限不足和不支持文件均有明确恢复路径。

## 11. 明确递延项

- 完整 WebGL/R3F、真实 3D 网格和模型资产管线。
- 全本地 Whisper/视觉/LLM 和 GPU Docker 透传。

- 人脸识别、声纹识别、人物自动确认、照片修复、语音克隆。
- 完整自由星图编辑器、复杂连接规则、自动人生时间线生成。
- 实体印制、付费墙、云端同步和生产级公网发布。

## 12. 成功的定义

用户不是看到一张漂亮但假的星图，而是可以在一片真实、可漫游的家庭宇宙里，把一段文字、照片、声音或日记安全地交给一颗家人星球；AI 谦逊地辅助整理，家人亲自确认，记忆真的发光、真的相连，并最终成为一封可传承的家书。
